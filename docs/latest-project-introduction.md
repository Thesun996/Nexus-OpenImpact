# Nexus OpenImpact 最新项目介绍

> 更新日期：2026-10-25（Asia/Shanghai）  
> 当前开发分支：`code-relation-graph`  
> 项目版本：V1 本地工作台  
> 文档用途：项目交接、组内汇报、比赛材料整理与功能验收。

## 1. 项目是什么

Nexus OpenImpact 是一个面向学生开发者和开源新贡献者的 **Python 代码变更影响分析助手**。

它主要回答一个问题：

> 如果修改一个函数、模块或公开符号，项目中的哪些代码可能受到影响，判断依据是什么？

系统不会自动修改用户代码，也不会依靠大模型猜测调用关系。核心结论来自 Python AST、符号索引、静态调用关系和确定性兼容规则，并为结果提供文件、行号、调用路径和源码证据。

## 2. 目标用户

- 刚开始参与 GitHub、Gitee 等开源项目的学生开发者；
- 会编写 Python，但不熟悉大型项目调用关系的开发者；
- 需要在修改函数接口前检查影响范围的课程或比赛团队；
- 希望通过具体代码证据理解 Direct、1-hop、2-hop 影响的学习者。

OpenImpact 是辅助理解和检查的工具，不替代人工代码审查、真实测试和开发者最终判断。

## 3. 当前核心流程

```text
上传 Python ZIP
  → 安全读取源码并建立项目快照
  → 选择函数、模块或公开符号
  → 配置计划中的代码变更
  → 校验变更是否合法
  → 创建本地分析任务
  → Worker 执行静态影响分析
  → 查看影响报告、代码证据和关系图
  → 保存、下载或重新打开历史报告
```

项目支持直接上传 ZIP，也支持先保存到本机项目库，再从已有快照继续分析。上传的源码只作为静态数据读取，不会被导入或执行。

## 4. 已实现功能

### 4.1 静态分析能力

- 递归发现 Python 文件并安全处理 ZIP；
- AST 解析、模块与函数索引；
- 明确 `import`、`from ... import ...` 和普通包相对导入解析；
- 静态可确认的函数调用关系；
- Direct、1-hop、2-hop 影响传播；
- 未解析调用、语法错误和覆盖范围诊断；
- 文件位置、行号、源码片段、调用路径和判断规则证据；
- 中文规则解释，可选接入 DeepSeek 生成受证据约束的解释。

### 4.2 支持的变更类型

函数签名领域：

1. 新增必填参数；
2. 删除普通参数；
3. 重命名参数；
4. 将已有可选参数改为必填参数。

模块和公开符号领域：

5. 模块重命名；
6. 模块删除；
7. 公开模块级变量或常量重命名；
8. 公开模块级变量或常量删除。

所有操作均为“计划变更分析”，不会直接修改源码。

### 4.3 Web 工作台

- 前端演示入口与工作台布局；
- ZIP 上传、项目概览和源码根目录选择；
- 函数、模块、公开符号目标选择；
- 变更配置、后端校验和签名对比；
- 分析任务状态与失败诊断；
- 影响报告、证据详情、源码阅读和相关测试提示；
- 报告追问与完整 JSON 下载；
- 本机项目库、快照版本、历史报告和任务列表；
- 黑紫与科技蓝两套主题；
- 桌面端和移动端响应式布局。

### 4.4 代码关系图

当前开发分支增加了代码关系图：

- 节点来自项目 AST 与符号索引；
- 连线只表示静态分析能够确认的函数调用；
- 支持查看函数定义位置与关系证据；
- 未解析调用单独列为待人工检查，不会画成确定关系；
- 支持节点选择、拖动和轻量动态布局；
- 项目完整图不可用时，可回退展示当前报告中的证据链。

它目前是 **V1 Python 函数调用关系图**，不是覆盖类、变量、数据库、外部服务和运行时行为的通用知识图谱。

## 5. 技术架构

| 层级 | 主要技术 | 职责 |
| --- | --- | --- |
| 前端 | React、Vite、原生 CSS | 上传、配置、任务、报告和关系图交互 |
| API | FastAPI | ZIP 检查、变更校验、任务、项目库和报告接口 |
| 分析核心 | Python 标准库 AST | 符号、导入、调用关系和影响规则 |
| 本地任务 | 独立 Python Worker | 从 SQLite 领取并执行分析任务 |
| 数据存储 | SQLite、本地快照目录 | 项目、ZIP 快照、任务和报告历史 |
| 可选解释 | 规则模板或 DeepSeek | 在已有证据范围内生成中文说明 |

总体数据流：

```text
ZIP / 本地样例
  → Repository Scanner
  → AST Parser
  → Symbol Index
  → Call / Import Graph
  → ChangeSpec Validator
  → Impact Engine
  → Evidence Builder
  → Rule / Optional LLM Explanation
  → Report and Relation Graph
```

## 6. 数据库与登录现状

项目已经具有本地 SQLite 数据库，用于保存：

- 本机项目；
- ZIP 快照及版本；
- 分析任务状态；
- 历史报告。

默认数据位于 `.openimpact/openimpact.sqlite3` 和 `.openimpact/snapshots/`，这些本地运行数据不应提交到 GitHub。

登录页面目前仍是前端演示入口。项目没有真实用户表、密码存储、会话认证和账号级数据隔离。比赛 V1 保留登录版面，但不把真实账号系统作为核心开发目标。

## 7. 当前能力边界

当前版本重点支持 Python 静态分析，存在以下边界：

- 不保证覆盖 Python 的全部动态语义；
- 不推断无法证明的方法分派、反射、动态导入和运行时对象调用；
- 不执行用户上传的项目或测试；
- 间接影响表示建议检查，不表示运行时必然失败；
- 未发现影响不等于证明整个项目没有风险；
- 当前关系图不等同于完整项目知识图谱；
- 不自动修改代码、提交 Git 或创建 Pull Request；
- 尚未建设生产级账号、权限、云端部署和分布式任务队列。

## 8. 本地运行方式

macOS 在仓库根目录分别打开三个终端：

```bash
./scripts/run-local-api.sh
./scripts/run-local-worker.sh
./scripts/run-local-frontend.sh
```

默认访问地址：

```text
http://127.0.0.1:5173/
```

若手工指定端口，前端、API 和 Worker 的配置需要保持一致。Vite 使用固定端口模式，端口占用时会直接报错。

Windows 推荐使用统一启动脚本：

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\scripts\start-local.ps1 -Provider rule
```

## 10. 尚未完成与后续建议

### 必须在比赛交付前处理

1. 完整手动验收并记录截图或演示视频；
2. 确认提交目录，排除数据库、快照、依赖、构建产物和临时文件；
3. 整理比赛技术报告、系统架构图、创新点和真实案例；
4. 确认是否需要公开部署，或明确采用本地运行演示；
5. 准备独立人工标注案例，说明准确性和当前覆盖边界。

### 可以继续优化但不阻塞 V1

- 关系图缩放、平移、搜索、筛选和较大项目布局性能；
- 更丰富的真实开源项目案例；
- Benchmark 与人工 Ground Truth；
- 部署脚本和演示环境；
- 更清晰的新手引导和错误恢复；
- 在明确需求后扩展新的 Python 变更类型。

### 当前不建议投入

- 真实账号密码和复杂权限系统；
- 自动修改代码或自动提交 PR；
- 多语言静态分析；
- 企业级协作平台；
- 没有静态证据支持的通用知识图谱关系。

## 11. 项目亮点

1. **变化驱动**：不是泛泛展示依赖，而是围绕一次具体计划变更分析影响。
2. **证据优先**：结论包含源码位置、调用关系、规则和覆盖诊断。
3. **静态分析与 AI 分工明确**：静态规则负责事实，AI 只负责受约束的解释。
4. **学生友好**：中文说明、可视化流程、示例 ZIP 和本地可复现演示。
5. **不执行陌生代码**：降低分析未知开源项目时的安全风险。
6. **可追溯**：项目快照、任务和报告可以本地保存和重新打开。

## 12. 一句话汇报版本

> Nexus OpenImpact 已完成一个可本地运行的 Python 代码变更影响分析工作台：用户上传项目 ZIP、选择函数或符号并配置计划变更后，系统通过 AST 和静态调用关系生成带文件位置、调用路径和中文解释的影响报告，同时支持项目快照、后台任务、历史报告及证据型代码关系图；当前重点仍是 V1 静态分析准确性和比赛演示，不做真实账号与自动改代码。
