## 一、项目定位与当前状态

Nexus OpenImpact 面向中文学生开发者和开源项目的新贡献者，帮助用户理解一个拟定代码变更可能影响哪些位置、影响如何沿依赖关系传播，以及应该先核查哪些源码和测试。

当前已经形成可在本地实际操作的 Web 闭环：上传 Python 项目 ZIP，读取项目，选择分析对象，配置变更，后端校验，执行分析，查看真实源码证据，并进一步阅读项目文件或围绕报告提问。

生产功能已集成到 `main`，覆盖三个分析领域、八种变更类型。当前成果包括静态分析 Core、CLI、FastAPI、React 工作流、中文报告、DeepSeek 辅助解释与报告追问、源码阅读窗口及基础测试定位。独立准确率评价、学生学习收益与公开部署能力尚未完成验收。

## 二、已经支持的八种变更

| 分析领域 | 用户操作 | 类型标识 | 当前行为与边界 |
| --- | --- | --- | --- |
| 函数签名 | 新增必填参数 | `add_required_parameter` | 构造候选签名，检查原调用是否从兼容变为不兼容；保留参数种类与可选插入位置配置 |
| 函数签名 | 删除参数 | `remove_parameter` | 支持仅位置、普通位置或关键字、仅关键字参数；拒绝删除 `*args`、`**kwargs` |
| 函数签名 | 重命名参数 | `rename_parameter` | 支持普通位置或关键字、仅关键字参数；纯位置调用可能保持兼容，仍使用旧关键字的调用可能产生直接影响 |
| 函数签名 | 将可选参数改为必填 | `make_parameter_required` | 仅移除指定参数的默认值；`None`、`False`、`0`、空字符串均属于有效默认值；产生非法签名顺序时拒绝配置 |
| 模块 | 重命名模块 | `rename_module` | 在虚拟模块布局中检查旧静态导入是否失去原目标；不真实改名用户文件 |
| 模块 | 删除模块 | `remove_module` | 在虚拟布局中检查模块消失引入的静态导入断裂；不真实删除用户文件 |
| 模块符号 | 重命名公开变量或常量 | `rename_module_symbol` | 检查原名称的明确导入、属性读取及受支持的模块内引用是否断裂 |
| 模块符号 | 删除公开变量或常量 | `remove_module_symbol` | 检查定义消失引入的明确符号引用断裂；动态写入等情况保持保守诊断 |

函数签名的变更目标仍为模块级函数。类方法、嵌套函数、类定义体和匿名函数中对明确模块级函数的调用已经进入检查范围，这些调用上下文没有因此成为新的变更目标。

模块与符号变更目前限定项目根目录下唯一、受支持的普通 `.py` 模块。包目录内的模块、`__init__.py`、特殊入口、歧义名称及标准库同名目标等不自动开放为可选目标。符号目标限定明确的公开简单赋值或有值注解赋值；复杂表达式、重复绑定、私有名称及动态导出等有明确限制。

具体载荷与参数边界见 [函数变更契约](change-types.md)、[模块变更契约](module-changes.md)、[符号变更契约](symbol-changes.md)。

## 三、完整使用流程

1. 用户从开源仓库或本地取得 Python 项目，保留文件和目录结构，压缩成 ZIP。
2. 打开网页，经过项目名开场与演示登录进入工作台。演示登录可留空，不验证、上传或保存账号密码。
3. 选择 ZIP，设置源码根目录并读取项目。普通项目使用 `.`；`src/package_name/` 布局通常填写 `src`。
4. 在函数、模块、模块符号三个领域中选择对象。候选来自真实 Inspect 结果；不支持的对象显示禁用原因。
5. 配置一种拟定变更，查看标为“待校验”的草稿预览。
6. 提交 Validate。只有后端通过后，修改后签名或虚拟变更才显示为已确认配置。
7. 提交 Analyze，查看直接影响、两层上游传播、人工检查项、未解析记录与覆盖情况。
8. 选择具体影响记录，联动查看真实路径、源码证据和中文说明；按需打开完整源码、查看测试候选或提交追问。

系统支持一次读取多个 Python 文件，并在受支持范围内分析跨文件关系。上传源码不会被执行、修改或应用拟定变更。网页只在当前会话保留原始 ZIP；刷新后需要重新上传。

Inspect、Validate、Analyze 重复使用同一原始 ZIP 与指纹。切换项目、源码根目录、分析对象、领域、变更类型或配置字段时，旧校验与报告按现有规则失效，旧请求被取消或其迟到响应被丢弃。

## 四、静态分析与证据架构

| 层次 | 已实现职责 |
| --- | --- |
| 项目输入 | 安全导入 ZIP、扫描 Python 源码、保存项目相对路径、校验原始 ZIP 指纹与源码快照 |
| 事实采集 | AST 解析、函数签名与调用上下文、模块与符号清单、Import 与名称绑定信息 |
| 领域模型 | 函数、模块、符号使用各自的不可变 ChangeSpec 与具体 Operation；模块变化不伪造函数签名 |
| 确定影响 | 函数比较前后调用兼容性；模块和符号比较虚拟变更前后的可靠静态绑定 |
| 上游传播 | 函数使用 Call Graph；模块和符号使用 Module Dependency Graph；支持多种子、循环控制、去重与最多两层上游 |
| Evidence | 保存真实文件、行列、源码片段、源码哈希、规则、原因与对应路径；缺失或不匹配时显示不可用 |
| Report 与解释 | 按领域输出真实结果；中文解释以结构化证据为输入；React 同步当前影响、路径、证据与解释 |

### 4.1 函数签名判定

核心条件为：**修改前调用兼容，修改后调用不兼容，才计入本次变更引入的确定直接影响。**

| 修改前 | 修改后 | 处理方式 |
| --- | --- | --- |
| 兼容 | 不兼容 | 本次直接影响 |
| 兼容 | 兼容 | 无新增不兼容 |
| 不兼容 | 不兼容 | 既有问题，不归因于本次变更 |
| 不兼容 | 兼容 | 兼容性改善，不计直接影响 |
| 无法静态证明 | 任意 | 人工检查或其他保守状态，不猜测为确定影响 |

四种参数操作共同使用前后签名绑定逻辑，没有分别建立独立的直接影响判断算法。

### 4.2 模块与符号判定

只有引用在修改前可靠绑定到项目目标，修改后因本次虚拟变更发生目标断裂，才形成确定的静态引用影响。名称相同、字符串包含、动态导入的参数看似匹配等条件均不足以直接确认目标。

这里的“确定”限定于已声明的静态模型。模块初始化、运行时搜索路径和实际执行分支没有被运行验证；上游传播表示需要检查的依赖关系，不表示上游必然运行失败。

### 4.3 报告与 API 兼容性

原函数报告保持 `schema_version=1`。模块和符号有各自的 `change_domain`、`report_kind` 与领域报告，版本也为 1；不会把模块导入数或符号引用数伪装成函数调用数。传播路径来自实际记录，展示的代表路径不被描述为完整项目调用图。

原 Inspect → Validate → Analyze 端点与旧函数请求继续可用。新增领域使用显式分发，并保留严格校验、错误指纹 409、非法或不支持配置 422 等行为。详见 [API 契约](api-contract.md)。

## 五、已完成的 Web 与辅助体验

### 5.1 三领域配置与中文报告

- 上传、对象选择、变更配置、分析报告四个页面共享 Tracework 设计系统。
- 配置页面区分草稿与后端已确认结果；类型切换清除无效配置和旧分析状态。
- 选择函数后，可直接在该行进入“配置变更”，避免大量函数时必须滚动到列表底部。
- 统计区分“确定影响”“影响传播”“分析边界”，提供中文帮助提示及鼠标、键盘、移动端触发方式。
- 普通用户界面将参数种类、状态、规则等映射为中文；原源码、函数名、参数名与 API 内部值保持不变。
- partial、人工检查、未解析及证据不可用状态保留，不在手机上隐藏关键诊断。

### 5.2 项目源码阅读窗口

上传并读取项目后，可通过右下角“项目源码”打开只读窗口，按相对目录寻找 Python 文件、搜索文件及文件内文字，并分段阅读长源码。报告证据和回答引用可跳转到真实文件及行号。

窗口支持键盘关闭、焦点约束和关闭后焦点恢复。源码可阅读与语义关系可确认是不同能力；扫描器忽略目录、非 Python 文件及不支持输入不会被当作完整项目阅读器的一部分。

### 5.3 中文解释与 DeepSeek 追问

静态分析先确定影响并生成 Evidence，解释层再组织中文说明。函数报告可按后端配置使用 DeepSeek；模块与符号报告目前保留规则说明。报告追问支持根据当前证据主动生成推荐问题，以及用户输入问题后的回答。

推荐追问和模型回答只在用户主动操作时请求，使用当前变更、选中记录、证据片段、有限路径及最近对话。密钥由后端读取，不置于前端或报告。模型不可用时，回答明确区分规则回退；推荐问题失败时不填充固定问题。

模型不能新增影响关系、修改统计或替代 Import/Symbol 解析。当前追问围绕已有变更报告，不提供任意全项目知识问答；在源码窗口打开其他文件，也不会自动把它加入模型上下文。自然语言仍需人工复核，解释置信度不代表代码运行失败概率。

DeepSeek 接入代码已存在，外部服务每次是否可用取决于有效密钥、网络及返回校验。本报告未重新发起真实模型请求，也不把旧文档中的认证失败、规则回退或 HTTP 200 记为当前模型成功。详见 [报告工作台](report-workspace.md) 与 [检查建议](explanation-check-guidance.md)。

### 5.4 相关测试定位

函数报告能够从已有确定直接影响和有限上游路径，定位命名符合规则的模块级测试函数。候选包含真实文件位置、检查理由、路径与源码快照，帮助用户确定先检查哪些测试。

当前没有执行、收集或验证上传项目的测试，也不覆盖测试类、复杂 fixture 分派和自定义框架。模块、符号报告暂不提供这套测试候选。候选为空、测试通过或报告零影响，都不能单独证明改动安全。详见 [相关测试定位](related-tests.md)。

### 5.5 入口、配色与动效

当前已采用用户确认的黑、紫、白配色。项目名使用单次逐字出现和散去动画，随后进入演示登录；点击登录后，登录页沿渐变蒙版消散，再显现上传页。

原页面切换、步骤指示、按钮反馈、函数选中、真实加载状态、传播路径呈现和 Evidence 联动保留。退出与进入按顺序处理，避免新旧文字重叠。重复登录不会重复初始化工作台，登录后业务 Provider 持续保留。

已有减少动态效果分支和受控偏好测试。**Windows 系统级 `native reduced-motion verification` 仍为 pending**，不能用模拟偏好替代负责人手动验收。详见 [入口与主题验收](brand-entry-acceptance.md)。

## 六、真实项目适用性与覆盖边界

### 6.1 已补充的解析能力

函数领域已支持显式源码根目录、普通 Python 包的明确绝对导入、静态相对导入及别名。解析会检查包层级、目标唯一性、局部或闭包遮蔽，以及已识别的名称或属性重绑定。

调用采集已覆盖具名函数、类方法、嵌套函数、类定义体和匿名函数中的明确模块级函数调用。类体与匿名函数通过源码位置描述调用上下文；创建匿名函数或声明类不会凭空增加外层调用边。

未确认关系按真实原因分类为源码与分析范围、绑定歧义与名称遮蔽、对象属性与动态调用、已识别的项目外或内置目标、目标未确认及其他诊断。未知记录保留，分类不会自动提高覆盖程度或减少漏检风险。

### 6.2 真实开源项目观察

| 项目与固定输入 | 已记录的观察 | 解释限制 |
| --- | --- | --- |
| Boltons 本地冻结源码 ZIP | 65/65 个 Python 文件语法解析成功；先前排除的 63 个类体/匿名函数调用全部进入收集与解析，其中 8 处确认项目函数目标、55 处仍未确认 | 进入解析不等于全部可靠绑定，覆盖状态仍为 partial |
| Boltons `cachedmethod` | 拟新增仅关键字必填参数 `strict`，真实装饰器调用产生 3/0/0，partial | 未执行 Boltons 测试，不声明运行结果 |
| Boltons `human_readable_list` | 参数 `delimiter` → `separator`，已记录 6/0/0，partial | 结果对应固定源码快照，不表示穷尽所有运行时调用 |
| python-dotenv v1.1.1 | 曾用于发现 src 布局、相对导入和调用作用域缺口；后续已有针对性的包路径与调用覆盖修订 | 初次审计数字属于历史快照，不能直接套用到最新版 |

上述是功能验证与源码观察，没有独立人工标注的准确率含义。具体输入、位置与阶段差异见 [调用覆盖](call-coverage.md)、[普通包支持](package-imports.md) 及 [真实项目差距审计](real-project-gap-audit.md)。较新的调用覆盖记录优先于旧包文档中仍保留的作用域限制描述。

### 6.3 仍然存在的能力边界

- 语法解析成功只证明能够读取 AST，不证明所有调用和导入关系已经确认。
- 对象方法分派、复杂继承、函数对象转发、动态导入、反射、运行时重绑定和复杂包重导出仍有限制。
- 普通包路径支持主要服务函数领域；模块和符号变更没有同步扩展到任意嵌套包目标。
- 星号展开参数与其他无法静态证明的输入保持人工检查，不自动计为确定影响。
- 上游传播最多两层，不能据当前代表路径推断完整项目依赖图。
- `complete` 表示声明的静态支持范围完成；`partial` 下零影响不能推出整个项目安全。
- 当前只分析拟定的一种受支持变更，不支持任意 Git Diff、跨语言分析、自动修复或默认值取值变化的业务后果分析。
- ZIP 有安全限额，当前原始上传上限为 5 MiB；大型项目可能需按真实分析边界准备输入。不能通过裁掉相关源码后继续宣称原项目完整覆盖。

## 九、对当前用户痛点的覆盖程度

| 用户问题 | 当前可以提供 | 尚需补充或验证 |
| --- | --- | --- |
| 找到引用后仍不清楚哪些会受此次修改影响 | 受支持范围内的前后兼容性或绑定比较，区分新影响、既有问题与不确定记录 | 复杂 Python 语义仍可能导致未确认关系 |
| 不清楚影响沿什么路径传播 | 真实静态边、两层上游与代表路径，对应源码位置 | 更深关系与运行时路径没有穷尽 |
| 缺少依据选择测试 | 函数领域的真实模块级测试候选、理由与路径 | 测试类、fixture、其他领域，以及推荐效果评价 |
| 输出简略，难以形成工程理解 | 中文证据说明、检查顺序、源码阅读与模型追问 | 学生能否更快理解项目尚需用户实验 |
| 面对陌生项目担心遗漏而不敢修改 | 已确认影响和未覆盖区域同时展示，避免用零结果承诺安全 | 无法保证复杂陌生项目完整覆盖，仍需测试与人工判断 |

现阶段有实际可操作的价值依据：定位分散的静态引用、给出有限传播关系、让用户回到源码核查。是否显著节省维护时间、提高学习收益，仍属于需要独立评价的假设。
