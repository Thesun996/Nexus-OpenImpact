# 样例 ZIP 使用指南

本文用于测试 Nexus OpenImpact 的核心前端流程：上传 Python ZIP、选择函数、配置函数签名变更、运行分析并查看影响报告。

## 测试入口

启动后端和前端后，在浏览器打开：

```text
http://127.0.0.1:5173/
```

使用样例压缩包：

```text
signature_change.zip
```

如果前端页面无法打开，先确认后端和前端开发服务都在运行，并且浏览器访问的是 Vite 前端地址，不是直接打开本地 HTML 文件。

## 1. 上传项目

在上传区域选择 `signature_change.zip`。

合理反馈：

- 页面显示项目名类似 `signature_change`。
- 能看到 Python 文件数量和函数数量。
- 覆盖状态应显示 `complete`。
- 页面允许进入选择函数步骤。

异常情况：

- 如果提示 ZIP 类型不对，确认上传的是 `.zip` 文件，不是解压后的文件夹。
- 如果提示后端连接失败，确认后端服务已启动。
- 如果页面白屏，打开浏览器控制台检查前端是否连接到了正确端口。

## 2. 选择函数

在函数列表中选择：

```text
utils.format_date
```

合理反馈：

- `utils.format_date` 这一行被选中。
- 文件应显示为 `utils.py`。
- 参数应显示为 `date`。
- 配置变更入口或下一步按钮变为可用。

## 3. 配置变更

选择变更类型：

```text
新增参数
```

新增参数名填写：

```text
timezone
```

参数类型选择：

```text
positional_or_keyword
```

点击“校验变更”。

合理反馈：

- 页面显示“校验通过”。
- 修改前签名为：

```text
format_date(date)
```

- 修改后签名为：

```text
format_date(date, timezone)
```

- `timezone` 应有轻微高亮。
- “开始分析”按钮变为可点击。

异常情况：

- 如果校验失败，检查参数名是否误填成 `/`、空格、中文或其他非法 Python 参数名。
- 如果“开始分析”不可点，说明还没有通过校验，或函数/参数配置已被修改，需要重新校验。

## 4. 开始分析

点击“开始分析”。

合理反馈：

- 无论是直接上传 ZIP，还是从项目库快照进入，页面都可能先显示任务状态，例如 `queued` 或 `running`，随后自动显示报告。
- 直接上传 ZIP 时，系统会在开始分析时自动保存当前 ZIP 快照，后续可以从项目库或任务页重新查看。
- 页面不应白屏，不应卡死，不应直接展示原始 JSON。

## 5. 查看报告

合理报告结果应包含：

- 直接影响：`1`
- 1-hop 间接：`1`
- 2-hop 间接：`1`
- 人工检查：`0`
- 未解析调用：`0`

直接影响应显示：

```text
report.report -> utils.format_date
```

位置应类似：

```text
report.py:5
```

代码证据应为：

```python
return format_date(date)
```

中文解释应表达：这里调用 `format_date` 时只传入了 `date`，但修改后的函数签名还需要 `timezone`，所以这个调用需要修改或检查。

## 通过标准

这个样例跑通时，说明以下核心业务链路正常：

```text
上传 ZIP -> 识别函数 -> 配置签名变更 -> 静态分析 -> 展示影响证据
```

如果使用项目库快照入口，还应额外确认：

```text
保存 ZIP 快照 -> 从项目库打开 -> 创建分析任务 -> 轮询任务 -> 读取已保存报告
```

## 不属于本样例验证范围

以下内容不是这个样例的验收重点：

- 真实登录。
- 多用户数据隔离。
- 生产级后台任务队列。
- 自动修改源码。
- 非 Python 项目分析。
