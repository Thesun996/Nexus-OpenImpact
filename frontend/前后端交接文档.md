## 4. 项目模式与演示模式

默认打开实际项目模式，函数、指纹、校验和报告均为空。选择文件或拖放 ZIP 后，原始 `File` 存在顶层。点击读取项目调用 Inspect，函数列表全部来自本次响应，目标通过完整 Symbol ID 选择；不预设实际项目一定存在 `utils.format_date`。配置完成后先 Validate，成功后再 Analyze。

用户点击“打开演示项目”才进入独立演示模式。页面显著显示“演示数据 · 固定样例，未调用后端”。演示 ZIP 会先核对 SHA-256，再加载已经保存的真实 rule 模式 HTTP 响应。只有以下配置能够展示保存的校验和报告：

```json
{"target_symbol_id":"utils.format_date","added_parameter":{"name":"timezone","kind":"positional_or_keyword"}}
```

流程为：打开演示项目 → 选择 utils.format_date → 配置变更 → 校验变更 → 查看演示报告。预期 Direct 1、1-hop 1、2-hop 1、coverage complete；点击各影响记录切换到对应源码和解释。

改变 Symbol、参数名、参数类型或 insert_before 后清空旧校验和报告，不能继续使用原样例。选择真实 ZIP 或“新项目”会清空演示状态。实际项目请求失败时不会切换到演示；演示也不向 DeepSeek 发请求。

## 5. 顶层状态与数据契约

`WorkflowProvider` 位于页面之外，通过 React Context + reducer 管理：

| 状态 | 内容 |
| --- | --- |
| file | 用户选择的原始 ZIP File；跨页面保持同一对象 |
| mode | project 或 demo |
| inspect | 完整 Inspect 响应及 symbols/modules/coverage/diagnostics |
| projectFingerprint | Inspect 的 project_fingerprint，初始为空 |
| selectedSymbolId | 完整 Symbol ID；不按函数短名识别 |
| change | parameterName、parameterKind、insertBefore |
| validation | 完整 Validate 响应；结构化签名位于 change_spec.before/after |
| report | 完整 Analyze Core Report |
| loading | inspect/validate/analyze 独立状态 |
| error | stage、code、message 和可选 diagnostics |
| revision | 防止旧异步结果覆盖新文件或配置 |

更换 ZIP 会清空 Inspect、指纹、目标、变更配置、Validate、Report 和旧错误。修改 Symbol 或参数配置会清空失效的校验与报告。所有业务请求由 `actions.js` 编排，结合 AbortController、revision 与活动请求身份检查；取消后仍晚返回的响应无法写入当前状态。活动请求锁避免正在请求时重复点击。健康检查状态独立于业务 error。

签名显示只格式化已有结构化参数，合法插入与校验留给后端。`buildChangePayload()` 构建简化配置，不构建新的 before/after 签名。无参函数显示 `page()`；新增参数后的正式签名取自 Validate 的 `change_spec.after`，不生成 `page(, zone)`。

Report 按 `direct_impacts`、`indirect_impacts` 的顺序关联 `evidences`，再核对 `explanations[index].evidence` 身份。同一行不同 column 的 Direct 调用不能混用证据。Evidence 不可用或对应关系缺失时保留影响记录，显示 unavailable；Explanation 缺失时显示不可用。

partial 明确提示范围不完整；零影响不能表示整个项目确定无影响。Indirect 表示上游路径建议检查，不能声称一定运行失败。兼容调用和 pre-existing problem 不计入 Direct；人工检查单独展示。

页面统一使用“中文辅助解释”。现有 API 没有模型来源/成功/fallback 标识，不能根据 HTTP 200、confidence 或解释非空宣称 DeepSeek 真实调用成功。联调后端明确使用 rule，无需 Key，不调用外部模型。

## 6. 真实 API 接入与恢复

Vite dev 代理已配置：

```js
'/api': { target: 'http://127.0.0.1:8000', changeOrigin: true }
```

不改写路径。`src/api/client.js` 统一使用相对 `/api/v1/...` 请求，通过同 Origin 的 Vite 代理到本地 FastAPI；页面不散落后端地址，本轮没有修改后端 CORS。该开发配置不代表最终生产部署地址。部署时需单独确认反向代理或明确的 Origin 白名单。

后端在原 main 工程的项目虚拟环境内启动，保持规则模式：

```powershell
cd E:\编译\2026人工智能算法精英赛新赛道\Nexus-OpenImpact
$env:OPENIMPACT_LLM_PROVIDER = 'rule'
.\.venv\Scripts\python.exe -m uvicorn openimpact.api:app --host 127.0.0.1 --port 8000
```

| 操作 | 接口 | 输入 |
| --- | --- | --- |
| 检查服务 | GET /api/v1/health | 无 |
| 读取项目 | POST /api/v1/projects/inspect | multipart: file |
| 校验变更 | POST /api/v1/changes/validate | multipart: file、change JSON string、expected_fingerprint 可选 |
| 分析项目 | POST /api/v1/projects/analyze | 同 Validate |

API Client 使用 fetch 与 FormData。Inspect 表单仅有 `file`；Validate 和 Analyze 再追加 `change=JSON.stringify(简化配置)` 与 `expected_fingerprint` 文本。不要手工设置 multipart 的 Content-Type，让浏览器生成 boundary；不把 change 作为文件或 Blob，也不追加服务器路径、查询参数或额外字段。

三个业务请求重复提交顶层同一原始 ZIP，因为后端 V1 不保留上传项目。客户端不从源码或 Inspect 结果重新打包、不替换用户选择的 File。Inspect 成功后保存实际 `project_fingerprint`，Validate/Analyze 正常流程始终携带该值。指纹核对 ZIP 原始字节；同样源码重新打包也可能改变指纹，不能照搬 docs/api-samples 或演示响应中的值。

Analyze 响应没有 project_fingerprint 字段，仍使用 Inspect 保存的指纹。参数 kind 为 positional_only、positional_or_keyword、keyword_only；insert_before 为顶层可选字段，值必须是目标函数已有参数名。不填写时使用后端默认位置；若产生非法签名，应展示诊断并由用户修改配置，不自行寻找合法插入点。

| 情况 | 响应与页面处理 |
| --- | --- |
| ZIP 无效、超限、不安全 | 展示安全 `error.code/message`，保留可重新选择文件的操作，不沿用旧函数与报告 |
| Inspect 成功但函数为空 | 显示空函数列表和 coverage/diagnostics，停止选择与后续分析 |
| 配置或签名校验失败 | 422 的 `validation.valid=false`；展示 `validation.diagnostics`，保留当前输入；`change_spec` 允许为 null，不继续分析 |
| 缺字段或表单错误 | 处理 FastAPI 的 `detail` 字符串或数组，不假设总有 error 对象 |
| 指纹不一致 | 409 `fingerprint_mismatch`；清空 Inspect、指纹、目标、配置及结果，保留原始 File 和错误诊断，要求重新读取项目；不省略指纹重试 |
| 安全 500、503 或后端不可达 | 展示服务/网络错误；不伪造空报告、不加载 Mock、不无条件重试失败请求 |
| 请求取消或旧响应晚返 | 当前项目/配置与结果保持不变，不把取消显示为新项目的错误 |

Analyze 保存完整真实 JSON，报告目标、统计、列表、Evidence 与 Explanation 均从该响应读取。真实零影响必须显示 0/0/0 和空影响列表，不保留上次报告的代码、目标、timezone 或解释。complete 只代表当前支持范围；partial 显著提示范围不完整，不能把零影响表述为全项目确定无影响。

不同阶段 coverage 不能强行相等：Inspect/Validate 包含解析、import 与符号诊断，Analyze 还考虑未解析调用。Evidence unavailable、Explanation null 与 manual_review 分别展示，不更改静态计数。源码和解释作为文本展示，不执行上传代码或插入未转义 HTML。
