## 1. 当前交接状态

前端第一版工作流已经完成，并且 `frontend/app.js` 已按正式接口契约接入真实 HTTP 入口：`inspectProject()`、`validateChange()`、`analyzeProject()` 会分别请求 `/api/v1/projects/inspect`、`/api/v1/changes/validate`、`/api/v1/projects/analyze`。

当前仍保留样例 ZIP 作为演示回退。由于 V1 后端没有数据库、项目 ID 或上传文件持久化，前端会把用户本次上传的 ZIP 作为 Blob 存在浏览器本地 IndexedDB，仅用于后续 validate/analyze 重新提交同一 ZIP；这不是登录态、历史报告或服务端项目持久化。清空浏览器数据或 IndexedDB 不可用时，需要重新上传同一个 ZIP。

当前页面已经覆盖：

1. 上传 Python ZIP。
2. 展示函数列表。
3. 选择目标函数。
4. 填写新增必填参数。
5. 校验 ChangeSpec。
6. 开始分析。
7. 展示影响报告、代码证据、中文解释和诊断信息。

登录、项目持久化、历史报告、后台任务、多项目管理暂不实现，只保留占位入口或规划中页面。

## 3. 当前前端接口入口

前端统一通过 `frontend/app.js` 中这三个函数调用后端：

```js
async function inspectProject(file) { ... }
async function validateChange(state) { ... }
async function analyzeProject(state) { ... }

window.OpenImpactApi = { inspectProject, validateChange, analyzeProject };
```

当前实现已经发起 `fetch` 请求。开发环境建议在 `frontend/` 目录下启动 Vite，让 `vite.config.js` 代理 `/api` 到本地 FastAPI 服务。

如需临时改后端地址，可在浏览器控制台或外部脚本设置：

```js
window.OPENIMPACT_API_BASE = "http://127.0.0.1:8000/api/v1";
```

正式联调仍建议使用同源代理，避免浏览器 CORS 问题。

## 4. 页面状态约定

前端当前保存在 `localStorage` 的 key：

```text
openimpact.frontend.state
```

主要状态字段：

```js
{
  fileName,
  zipSource,
  uploadStatus,
  inspect,
  selectedSymbolId,
  parameterName,
  parameterKind,
  validation,
  report,
  validationLoading,
  validationError,
  analyzeLoading,
  analyzeError
}
```

换 ZIP、换目标函数或修改新增参数后，前端会清空旧的 `validation` 和 `report`，避免旧结果误导用户。

语言切换保存在：

```text
openimpact.frontend.language
```

## 5. 后端接口期望

当前项目文档里的正式业务接口为：

| 方法 | 路径 | 用途 |
| --- | --- | --- |
| `POST` | `/api/v1/projects/inspect` | 上传 ZIP，返回项目模块、函数列表、覆盖情况 |
| `POST` | `/api/v1/changes/validate` | 上传同一个 ZIP 和 change 配置，校验新增参数是否合法 |
| `POST` | `/api/v1/projects/analyze` | 上传同一个 ZIP 和 change 配置，返回完整影响报告 |

三个接口都使用 `multipart/form-data`。前端不要手动设置 `Content-Type`，让浏览器自动带 boundary。

## 6. inspect 接入要求

前端上传字段：

```js
const form = new FormData();
form.append("file", file);
```

请求：

```http
POST /api/v1/projects/inspect
```

前端需要的返回字段：

```js
{
  project_name,
  project_fingerprint,
  source_root,
  modules,
  symbols,
  coverage,
  diagnostics
}
```

`symbols[]` 必须至少包含：

```js
{
  symbol_id,
  file,
  line,
  parameters
}
```

前端会把完整 `symbol_id` 作为后续目标函数 ID，例如：

```text
utils.format_date
```

## 7. validate 接入要求

前端需要重新上传同一个 ZIP，并发送 change 配置和 inspect 返回的 fingerprint。

建议请求体：

```js
const change = {
  target_symbol_id: state.selectedSymbolId,
  added_parameter: {
    name: state.parameterName,
    kind: state.parameterKind
  }
};

const form = new FormData();
form.append("file", file);
form.append("change", JSON.stringify(change));
form.append("expected_fingerprint", state.inspect.project_fingerprint);
```

请求：

```http
POST /api/v1/changes/validate
```

前端需要的成功返回字段：

```js
{
  project_name,
  project_fingerprint,
  coverage,
  change_spec,
  validation,
  diagnostics
}
```

校验通过：

```js
validation.valid === true
```

校验失败时仍然要返回可展示的诊断：

```js
validation.valid === false
validation.diagnostics[]
```

前端会显示 `validation.diagnostics[].message`，并禁止进入分析。

## 8. analyze 接入要求

前端同样重新上传同一个 ZIP，并发送相同 change 和 fingerprint。

请求：

```http
POST /api/v1/projects/analyze
```

前端报告页需要这些字段：

```js
{
  schema_version,
  change,
  validation,
  coverage,
  summary,
  direct_impacts,
  indirect_impacts,
  evidences,
  explanations,
  manual_reviews,
  pre_existing_problems,
  diagnostics
}
```

当前报告页已经展示：

- `summary.direct_impact_count`
- `summary.indirect_1hop_count`
- `summary.indirect_2hop_count`
- `summary.manual_review_count`
- `summary.unresolved_call_count`
- Direct Impact 列表
- 1-hop / 2-hop Indirect 列表
- 代码证据卡片
- 中文解释
- 诊断 / 分析限制

## 9. 错误处理约定

前端需要后端尽量保持以下错误形状之一。

普通错误：

```json
{
  "error": {
    "code": "fingerprint_mismatch",
    "message": "ZIP 指纹与此前 inspect 结果不一致。"
  }
}
```

校验失败：

```json
{
  "validation": {
    "valid": false,
    "diagnostics": [
      {"code": "invalid_change_spec", "message": "新增参数名不能为空。"}
    ]
  }
}
```

FastAPI 框架错误：

```json
{
  "detail": []
}
```

前端联调时需要至少处理：

- ZIP 过大。
- 非 ZIP 文件。
- ZIP 损坏。
- 没有 Python 文件。
- fingerprint 不一致。
- validate 返回 `validation.valid=false`。
- analyze 内部失败。
- `coverage.status = partial`。

## 10. 诊断展示约定

报告页已有“诊断 / 分析限制”区。

如果返回：

```js
coverage.status === "partial"
```

前端应明显提示：

```text
分析范围不完整，未报告影响不代表整个项目一定没有影响。
```

诊断项不要混入确定影响列表。应单独展示：

- `diagnostics.parse_errors[]`
- `diagnostics.unresolved_imports[]`
- `diagnostics.unresolved_calls[]`

## 12. 前端当前不做的事

这些不属于当前前端交接范围：

- 登录。
- 用户权限。
- 项目持久化。
- 历史报告真实查询。
- 后台任务队列。
- 多项目管理。
- 在线 GitHub 仓库导入。
- 自动修改代码。
- 自动提交 PR。

当前只保留导航或占位页，避免按钮无反应。

## 13. 后续接入建议

`frontend/app.js` 中的三个入口函数已经按正式路径发起请求：

1. `inspectProject(file)` 请求 `/api/v1/projects/inspect`。
2. `validateChange(state)` 请求 `/api/v1/changes/validate`。
3. `analyzeProject(state)` 请求 `/api/v1/projects/analyze`。

下一步重点不是继续替换 Mock，而是确认本地开发启动方式、CORS/代理、以及 V1 不做服务端项目持久化的产品边界。当前前端可用浏览器本地 IndexedDB 暂存 ZIP 串起一次工作流；如果后续需要跨设备、跨浏览器、历史报告或后台任务，仍需要后端提供项目持久化/临时项目 ID。
